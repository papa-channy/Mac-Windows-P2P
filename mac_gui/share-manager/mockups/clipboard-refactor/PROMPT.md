# 역할

너는 데스크톱 앱 UI/UX 디자이너이자 프론트엔드 아키텍트다. 아래
**클립보드 기록 페이지**를 디자인 관점에서 리팩토링하는 작업을 맡았다.
최종 산출물은 (1) 기능 고도화 제안 리스트, (2) 레이아웃 재구조화 방향,
(3) 샘플 HTML 목업이다.

# 제품 맥락

- **제품**: Mac ↔ Windows 두 컴퓨터를 **로컬 직결망(LAN/SMB 공유 폴더)**
  으로 연결해 파일·클립보드·메모를 주고받는 데스크톱 앱. (인터넷 클라우드를
  거치지 않는 P2P 방식.)
- **기술 스택**: Tauri v2 (Rust 백엔드) + React + Vite. 순수 CSS (Tailwind
  미사용, 디자인 토큰은 CSS 변수). **라이트 테마** 기준.
- **UI 언어**: 한국어 (영어 병기 일부). 데스크톱 창 (최소 980×600,
  기본 1320×880). 모바일 아님 — 데스크톱 마우스/키보드 환경.
- **디자인 톤**: 미니멀, 라이트, 정보 밀도 적당히 높음. 파란색 계열
  primary accent. macOS 네이티브 앱 느낌에 가깝게.
- **이 페이지의 본질**: 두 컴퓨터가 각자 OS 클립보드에 복사한 내용을
  **자동으로 기록해서 한 타임라인에 합쳐 보여주는** 화면. 어느 쪽
  컴퓨터에서 복사하든 양쪽 앱에서 그 기록을 보고, 클릭하면 내 컴퓨터
  클립보드로 가져올 수 있다. (= 두 컴퓨터의 클립보드 히스토리 통합 뷰)

> 참고: 예전엔 이 페이지 상단에 "공유 텍스트"(한 칸짜리 메시지를 양쪽이
> 덮어쓰며 공유) 위젯이 있었으나, 별도의 "공유 메모" 페이지와 기능이
> 중복되어 **제거했다.** 따라서 이 페이지는 클립보드 자동 기록 타임라인
> 하나에만 집중한다. 텍스트 메시지를 양쪽이 공유·편집하는 기능은
> 고려하지 마라 (다른 페이지 담당).

# 현재 페이지가 제공하는 기능 (정확한 인벤토리)

이 페이지는 위에서 아래로 2개 영역으로 구성된다.

## 영역 1 — 페이지 헤더

- 제목: "📋 클립보드 (양쪽 통합)"
- 부제: "양쪽 호스트가 OS 클립보드를 1.5초마다 자동 기록 · 이미지 30일
  보관 후 자동 정리 · 항목 클릭 → 내 OS 클립보드로 복사"
- 버튼 `↻ 다시 읽기` — 수동 새로고침 (평소엔 2초마다 자동 폴링)
- 버튼 `🗑 내 기록 지우기` — 내 컴퓨터가 만든 클립보드 기록 전체 삭제
  (confirm 다이얼로그). 상대 컴퓨터 기록은 안 지움.

## 영역 2 — 클립보드 타임라인 (이 페이지의 핵심)

> 양쪽 컴퓨터가 OS 클립보드에 복사할 때마다 **자동으로 계속 쌓이는**
> 기록 스트림. 텍스트와 이미지가 시간순으로 누적된다. (현재 최대 200건
> 로드, 2초 폴링)

- 정렬 탭 2종:
  - `⏱ 최신순` — 시간 역순 평면 리스트
  - `👥 호스트별` — 컴퓨터별로 그룹핑 (Mac 먼저, 그 다음 알파벳순).
    각 그룹 헤더에 [OS 뱃지 + 호스트명 + N건]
- 우측: "총 N건" 카운트
- **텍스트 항목**: [OS 뱃지(Mac/Win) + 호스트명 + 상대시간 "3분 전"] +
  본문(최대 600자 미리보기, URL이면 강조 스타일). 클릭 → 내 OS 클립보드로
  복사
- **이미지 항목**: [OS 뱃지 + 호스트명 + 상대시간] + 썸네일 이미지 +
  메타(가로×세로 · NN KB). 클릭 → 이미지를 내 OS 클립보드로 복사.
  로드 실패/만료 시 "이미지 로드 실패 / 만료됨" placeholder
- 기록 없을 때: 빈 상태 ("기록이 없어요 / 텍스트나 이미지를 복사하면
  자동으로 여기 쌓여요")

# 현재 알려진 UX 문제점 (참고)

1. **항목 관리 기능이 전혀 없다.** 검색·필터·개별 삭제·즐겨찾기(핀 고정)가
   없어서, 200건이 쌓이면 원하는 항목을 찾기 어렵다.
2. **타입(텍스트/이미지/URL/코드)이 한 흐름에 섞여** 있어 "방금 복사한
   그 이미지" 또는 "어제 그 URL"을 빠르게 찾기 힘들다.
3. **항목 클릭의 유일한 동작이 "복사"뿐.** 미리보기 확대, 파일로 저장,
   원본 보기, 공유 메모로 보내기 같은 후속 액션이 없다.
4. **항목 하나하나가 정보 밀도가 낮다.** 긴 텍스트는 600자로 잘리지만
   펼쳐보기가 없고, 코드/URL/일반텍스트가 동일하게 렌더된다.
5. **민감정보 무방비.** 비밀번호·토큰·API 키를 복사하면 그대로 타임라인에
   평문 노출된다 (마스킹/제외 옵션 없음).
6. **시간 흐름 파악이 약하다.** "오늘 / 어제 / 지난주" 같은 시간 구획이
   없어 스크롤만 길어진다.

# 디자인 제약 (반드시 지킬 것)

- 데스크톱 가로 레이아웃 (좁은 모바일 아님). 좌측에 앱 전역 사이드바가
  이미 있으므로 이 페이지는 그 **오른쪽 메인 영역** 안에서만 동작.
- 라이트 테마. 과한 색/그라데이션 지양, 정보 위계가 명확한 미니멀.
- 한국어 라벨 유지 (영어 병기는 선택).
- **단일 책임 유지**: 이 페이지는 클립보드 자동 기록 타임라인 전용.
  "양쪽이 텍스트 메시지를 공유/편집"하는 기능(공유 메모)은 추가하지 마라.
- 기존 핵심 기능(자동 기록, 클릭-복사, OS별 그룹핑, 이미지 썸네일,
  Mac/Win 출처 구분)은 유지하거나 더 낫게.
- 두 컴퓨터(Mac/Win)의 출처 구분은 이 앱의 정체성이므로 **시각적으로
  명확히** 유지.

# 너에게 요청하는 것 (3단계, 순서대로)

## 1단계 — 기능 고도화 리스트업

위 현재 기능과 문제점을 바탕으로, 이 클립보드 기록 페이지에 **추가하거나
개선하면 좋을 기능을 10~20개** 제안하라. 각 항목마다:
- 기능 이름
- 한 줄 설명
- 해결하는 사용자 문제
- 구현 난이도 (상/중/하) 추정
- 우선순위 (must / nice-to-have / experimental)

특히 다음 방향을 적극 고려:
- 검색 (내용/호스트/타입 기준) 및 필터
- 타입별 뷰/탭 (전체 / 텍스트 / 이미지 / URL / 코드)
- 즐겨찾기·핀 고정 (자주 쓰는 항목 상단 고정)
- 개별 항목 삭제, 다중 선택 후 일괄 삭제/복사
- 항목 미리보기 확대 (이미지 라이트박스, 긴 텍스트 펼치기)
- 후속 액션 (파일로 저장, 공유 메모로 보내기, 원본 열기)
- 시간 구획 (오늘/어제/이번 주 헤더)
- 민감정보 마스킹/제외 (비번·토큰 패턴 감지)
- 키보드 단축키 (↑↓ 이동, Enter 복사, ⌘F 검색)
- 코드/URL 자동 인식 및 전용 렌더 (문법 하이라이트, 링크 프리뷰)

## 2단계 — 레이아웃 재구조화 방향

1단계 기능들을 담을 **새 레이아웃 구조**를 2~3개 안으로 제안하라. 각 안마다:
- 화면 분할 구조 (예: 상단 검색·필터바 + 리스트 / 좌측 리스트 + 우측 상세
  프리뷰 마스터-디테일 / 타입별 컬럼 등)
- 검색·필터·정렬을 어디에 배치했는지
- Mac/Win 출처 구분을 어떻게 시각화했는지
- 핵심 액션 버튼들의 배치 논리
- 장단점

ASCII 와이어프레임으로 구조를 먼저 보여줘도 좋다.

## 3단계 — 샘플 HTML 목업

2단계 안 중 **가장 추천하는 1개**를 골라, 실제로 렌더되는 **자기완결적
샘플 HTML 파일**로 만들어라. 요구사항:
- 단일 `.html` 파일 (인라인 `<style>` 포함, 외부 의존성 없음).
- 라이트 테마, 한국어 라벨, 위 제약 준수.
- 더미 데이터로 채워서 (타임라인에 텍스트 5~6건 + URL 2건 + 코드 1건 +
  이미지 3건, OS는 Mac/Win 섞어서, 시간도 방금~며칠전 다양하게) 실제
  모습이 보이도록.
- 검색바·필터/타입 탭·정렬·뱃지·핀·호버 상태·항목 액션 등 인터랙션
  요소를 CSS로 표현 (JS는 최소).
- 반응형보다 **1320px 폭 데스크톱 기준** 픽셀 완성도 우선.
- Mac/Win 출처 구분이 한눈에 드러나게.

출력은 1단계 → 2단계 → 3단계 순서로, 각 단계를 명확히 구분해서 제시하라.
